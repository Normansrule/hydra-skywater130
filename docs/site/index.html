HYDRA-130

Adaptive hardware scheduling and accelerator research. A dispatcher predicts how long each engine would take a piece of work, sends it to the cheapest, measures what happened and corrects its own model. What runs depends on the build: each view below names one.

As builtThe tileIP library RoadmapAreaBoard images VerificationNot done

Status. Not a complete or board-qualified CPU/GPU/TPU system. No image has run on a physical board. No CPU or GPU is integrated, and fully homomorphic encryption and sequestered execution are specifications, refused by the host driver. The Tiny Tapeout tile is the scheduler alone. See docs/verification/capability-matrix.md.

What has not been done

  • v3.8 at 4x4 hardened clean on 2026-10-18 (v3.6 settings; the scheduler's eligibility input tied off; netlist proved equivalent to v3.7's): DRC, LVS, antenna 0, setup +10.064 ns and hold +0.108 ns worst corner, 48.7%, 21/21 gate level.
  • Slew: 5,039 on v2; 3,665 on v3.2; 4,197 on v3.4; v3.5 (no buf_1) failed setup and was rejected; v3.6 (no weak or delay buffers at all) 775, only at the three slow corners (max_ss 775, nom_ss 559, min_ss 322), capacitance 0. FIRST_TRY.md requires 0. v3.7, the same design re-placed after a textual netlist change, ended at 1,333 (slow corners only) and capacitance 1: the count moves with placement, not only with settings. v3.8: 1,164 slew, capacitance 0.
  • The butterfly engine's area at q=8380417 (ML-DSA) is not yet measured: its 46-bit products make it the slowest of the three to synthesise. q=12289 and q=3329 are measured.
  • Never run on hardware. The bring-up image is built and simulated; docs/FPGA_BRINGUP.md is the procedure, and LED polarity is still an assumption until a board confirms it.
  • Full SkyWater chip never hardened: no LibreLane run of the OpenFrame chip has completed, so it has no gate-level netlist, timing sign-off, DRC or LVS result. (The Tiny Tapeout tile HAS: v3.4 sign-off clean on 2026-10-17.)
  • Two board images (ecp5-evn-sys, ecp5-evn-tpu) predate the content-hash rebuild rule, so their provenance is unknown until each is rebuilt once; `make -C fpga/build/ provenance` then says whether a bitstream matches the current sources.
  • No boundary scan: there are no scan cells at the pads, so SAMPLE, PRELOAD and EXTEST are absent and the chip is not boundary-scan testable.
  • The test port cannot reach registers if the system clock is dead: the bridge waits and reports busy. Reading with the system clock stopped would mean running the register file on the probe's clock.
  • Measured boot has its hardware half -- image bytes in, SHA-256 padded in hardware, PCR extended, on one core (hydra_measure) -- but nothing drives it yet: no boot ROM or core issues the measurements.
  • The security instructions are a verified functional unit, not yet wired into a RV64 pipeline; until they are, no core on this chip has them.
  • The Basys 3 bring-up image is simulated and its constraints generated, but no bitstream has been built: that needs Vivado or the openXC7 flow on your machine. The larger HYDRA images have not been ported to the Artix-7.
