HYDRA-130

A hardware scheduler that predicts how long each compute engine would take a job, sends the job to the cheapest engine allowed to run it, measures what really happened and corrects its own model.

Status by revision. The Tiny Tapeout tile v3.10 is the scheduler alone and has a clean sign-off record from one harden; it is not fabricated or tested silicon. The full OpenFrame chip is simulated and has never been hardened. No FPGA image has run on a board. Security blocks are checked IP in no build.

Physical layout of the tile

Placed cells of the v3.10 harden recorded in docs/timing.json (harden ladder run 20261018-174736, netlist 11f8262528e0, built from project.v 2b783f00cf0a): utilisation 48.6%, setup +14.06 ns, 1,230 slew warnings, DRC 0, LVS 0. This is a different run from the one the status above quotes unless the two names match.

This v3.10 layout was hardened from project.v as it stood before the reset synchroniser was rewritten for the SYNCASYNCNET lint warning; the build thread proved the two netlists equivalent (reports/fpga-harden-2026-10-17/tile-netlist-equivalence-rstsync.log.gz). Cells are attributed by the names in the hardened netlist.

There are no module rectangles on a flattened layout. Each dot is one placed standard cell. A cell is coloured by an RTL instance only when the netlist says so: named cells drive a net that keeps that instance's hierarchical name (mostly registers); inferred cells (lighter) drive only that instance's named registers. Everything else is shown as unattributed, buffers, clock tree, hold or antenna cells. One module's cells are spread across the die, which is the point.

Scripting is needed to draw the cells; the counts are listed here.

    From any state: TMS=1 x5 -> TEST_LOGIC_RESET, IR=0x1 (IDCODE). TMS=0 -> RUN_TEST_IDLE.     Unknown instructions select the 1-bit bypass register (line 171). There is no busy handling here; the bridge reports busy in user_capture.

    Clock crossing

    control

    Carries one {rw, addr, wdata} request from the TCK domain to the system clock domain and the read data back, using a toggle request and toggle acknowledge each through a two-flop synchroniser; the payload crosses unsynchronised but held stable for the whole handshake.     Two domains. TCK side: req_tog, busy, payload, ack_tog, ack_sync[1:0], rdata_q reset by trst_n (async, active low) (lines 85-88). clk side: req_sync[1:0], req_seen, ack_tog_sys, strobes, rdata_sys reset by rst_n (lines 119-123) and reg_we_q/reg_re_q (lines 145-149).       The Tiny Tapeout tile

      The tile is the scheduler and nothing else: no CPU, GPU, TPU or security hardware. Work and completions are outside it: the host sends a descriptor, reads the decision, and reports when the job finished with COMP. The pins below are read from info.yaml and checked against the wrapper's own assignments.

      Clock, reset, enable

      • Clock: 15.15 MHz declared (clock_hz), 66 ns, the sign-off period of v3.10.
      • Reset: rst_n is asynchronous in, released synchronously by a two-flop synchroniser, so the design leaves reset on a clock edge.
      • Enable: ena is not used by the design.
      • Idle levels: CSn idles high; SCK idles low (mode 0); unused inputs are ignored; every uio pin is an output.
      • SPI: SCK at most clk/8, oversampled by the system clock. byte 0 = {rw, addr[6:0]} (rw = 1 reads); bytes 1..N data, most significant first; a write commits when CSn rises, only if exactly LEN data bytes arrived.
