HYDRA-130

A dispatcher that predicts how long each engine would take, sends the work to the cheapest one, then measures what actually happened and corrects its own model. Three arithmetic engines, a scratchpad, and a host link — verified against independent models, proved where proof is cheaper than testing, and honest about what has not been built yet.

Each engine is compared against a model written from its contract rather than from its code, so a misreading of the specification shows up as a disagreement instead of being copied into both. Where a property is cheaper to prove than to sample — a port contract, a completion that must fire once — it is proved. Mutation testing then asks the only question that matters about a test suite: if the design were broken, would anything fail?

What has not been done

  • The v3 research tile (3x4, 113,939 um^2 by synthesis) has not been hardened. Its utilisation is an estimate (about 70%) from v2's LibreLane-to-yosys ratio; if placement or routing fails, tiles goes back to 4x4.
  • 5,039 slew and 20 capacitance warnings on the signed-off v2 tile. Not sign-off failures; tools/slew_report.py names the overloaded drivers. Re-read them on the v3 harden.
  • The butterfly engine's area at q=8380417 (ML-DSA) is not yet measured: its 46-bit products make it the slowest of the three to synthesise. q=12289 and q=3329 are measured.
  • Never run on hardware. The bring-up image is built and simulated; docs/FPGA_BRINGUP.md is the procedure, and LED polarity is still an assumption until a board confirms it.
  • Full SkyWater chip never hardened: no LibreLane run of the OpenFrame chip has completed, so it has no gate-level netlist, timing sign-off, DRC or LVS result. (The Tiny Tapeout tile HAS: sign-off clean on 2026-10-05.)
  • Two board images (ecp5-evn-sys, ecp5-evn-tpu) predate the content-hash rebuild rule, so their provenance is unknown until each is rebuilt once; `make -C fpga/build/ provenance` then says whether a bitstream matches the current sources.
  • No boundary scan: there are no scan cells at the pads, so SAMPLE, PRELOAD and EXTEST are absent and the chip is not boundary-scan testable.
  • The test port cannot reach registers if the system clock is dead: the bridge waits and reports busy. Reading with the system clock stopped would mean running the register file on the probe's clock.
  • Measured boot has its hardware half -- image bytes in, SHA-256 padded in hardware, PCR extended, on one core (hydra_measure) -- but nothing drives it yet: no boot ROM or core issues the measurements.
  • The security instructions are a verified functional unit, not yet wired into a RV64 pipeline; until they are, no core on this chip has them.
  • The Basys 3 bring-up image is simulated and its constraints generated, but no bitstream has been built: that needs Vivado or the openXC7 flow on your machine. The larger HYDRA images have not been ported to the Artix-7.
